# RG35XX 数字音频选型
日期：2026-11-08（Asia/Shanghai）
范围：CPyMO数字音频精度与相对计算开销；按用户最新指示，不测试/补偿扬声器失真。
结论：保留当前核心16抽头、512相位和连续终点、线性正常混音、过载联动限峰及音频线程保护。前端明确选择sinc/quality=2（LOWER，1:1标量8抽头），避免最低档实现受SIMD编译影响；关闭默认10秒PCM录音，诊断按需开启。没有改音量、EQ、游戏音乐或字体布局。

## 核心候选

同一生产解码/混音代码只变抽头、相位参数，24抽头为防32位累加溢出改用64位累加。40组解析正弦覆盖44.1kHz的1/10/16/19kHz，22.05kHz的1/7/9.5kHz，48kHz的18kHz。残差SNR和幅度分别计算，不把频响衰减藏入拟合。精度测试对照独立数学信号，不依赖生产解码器作为真值。

真实音乐选梦见bgm00/bgm09/bgm16，使用此前FFmpeg独立解码的原始44.1kHz PCM，取原第12–20秒无损包成WAV，比较每候选的生产重采样输出与96点双精度窗化sinc参考。按Q16实际时钟和每种抽头的群延迟对齐，排除开头0.1秒，不使用本核心重采样结果构造参考。

下表三首素材残差SNR为数字参考误差，单位dB，不是人耳评分。右列以当前核心为100%，分别为单路真实MP3、三路相同MP3模拟三声道的ARM/uClibc/QEMU CPU中位数；每次生成30秒，3轮交替顺序，计时含混音/解码和向/dev/null写出，不含建表启动成本。不表示真实掌机CPU占用，也不模拟真实BGM/VO/SE不同码率组合。

| t8p512 | 51.5 / 73.6 / 43.4 | 104% / 95% |
| t12p512 | 64.3 / 72.8 / 56.0 | 96% / 99% |

8/12抽头在明亮素材上误差明显更多，而此MP3场景没有一致的大幅开销优势。16/256节省约8KB/声道表内存，但三声道CPU未改善、精度略降；不为这点不确定收益更换已验证实现。24抽头改善高频解析信号，在三首真实片段中仅一首改善，三声道中位开销约增25%；未选。

## 前端候选

直接编译RetroArch v1.14.0官方nearest和sinc驱动，分别构建标量及ARMv7 NEON实现，比较nearest、sinc最低档1、低档2、中档3。48组解析信号覆盖1/10/18/21kHz和比例1、0.999、1.001。72组CPU测试覆盖4档×2实现×3比例×3轮，每组处理300秒输入，交替顺序。±0.1%是敏感性条件，不是测得的掌机时钟偏差。

1:1时nearest除最初跳过2帧外，输出与随机输入逐位一致，是已知严格同率情况下最省事的方案；一旦存在微小比例差，它会重复/跳采样点。标量1kHz测试在±0.1%时，nearest残差SNR约28dB，LOWER约57–61dB。18kHz时不同sinc档位的通带/误差取舍不同，不能按档位越高就对所有频率越好来判断。

更正前述工程说明：质量枚举0=DONTCARE、1=LOWEST、2=LOWER、3=NORMAL；设置值直接转换为该枚举。quality1在1:1的标量实现为4抽头，NEON会对齐到8；quality2在1:1为8抽头。下采样时还会按带宽及SIMD对齐增加抽头，因此“固定8抽头”不是对所有比例都成立。只引用侧瓣参数或忽略枚举映射不足以确定实际抽头。

选quality2作为明确的低档折中：不要求输出协商必须严格1:1，标量分支比最低档更好处理微小比例差，又避免中档更高开销和不同截止频率。1:1的NEON实现里quality1/2相同；额外比较10秒随机输入及1.001比例，两个档位输出逐字节相同。因此当前设备若走NEON且比例约1，这项配置收敛不会带来音效变化，也不承诺可闻提升。实际设备的SIMD分支和协商比例未从设备驱动日志确认，不能把参考构建结果冒充安装二进制实测。

在本次NEON/QEMU 1:1测试中，LOWER处理300秒输入的中位CPU为1.91秒，中档5.92秒；这些只是相同模拟环境中的相对滤波开销，不是设备播放占用百分比。

## 落地范围

核心和解码器原样保留，不重新编译或替换核心；配置补丁只含CPyMO.sh与retroarch-cpymo.cfg。全局RetroArch/音量、字体、字号、Logo/菜单行为保持reading9版本。
默认不再申请写满10秒PCM缓存，不产生新WAV；保留小型耗时/接收统计。静态缓存仍有虚拟地址空间，关闭后不会因采样写入而提交约1.92MB数据页，也避免正常退出写约1.92MB文件。原有WAV不删除；以audio-status.txt的capture_frames与capture_file_updated判断本次是否更新。
需要临时采样可设置CPYMO_AUDIO_DIAGNOSTICS=1，或显式给出CPYMO_AUDIO_CAPTURE路径。常规运行不加新选单。
这次选型针对现有44.1kHz游戏音乐、22.05kHz语音及48kHz输出；不声称所有高采样率/所有设备上的全局最优。

原始证据：evidence/core-summary.json、core-music-quality.json、frontend-summary.json、frontend-neon-equivalence.json。全部测试是数字及目标代码模拟，不做扬声器补偿，也不判断听感胜负。
