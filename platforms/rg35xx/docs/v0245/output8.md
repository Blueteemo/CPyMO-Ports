# v0.24.5 output8：布局与播放链路诊断

本轮用户反馈《梦见之药》音乐仍发炸，而其他模拟器正常；降低到很小音量也不能满足正常使用。当前无真机录音，不能宣称炸音已修复。字体未定，保持上一轮已经装卡的CPyMOReading350。源码中default.ttf从audio7时期的400对齐到现装350；不是本轮写卡换字体。

正文内缩0.4375em→0.375em，在640×480输出上约再左移2px，右边界固定；人名与垂直位置保持。START时间按真实字形左界、顶界补偿bearing，使左/上边距相等（27组像素测量误差≤1.1px），十行菜单原有底部留白保留。

音频DSP保留audio7实现，不增加压缩、EQ，也不降低输出比例或系统音量。实际卡上Yume与水仙全部36首音乐与原验收素材逐字节一致；3首Yume曲目前30秒在44100Hz直接比较FFmpeg独立解码与生产minimp3，去除编码延迟后最大2 LSB差，SNR约75–79dB；不能据此排除后续混音/播放问题。

原卡全局RetroArch使用nearest。仅CPyMO私有追加配置试用sinc/quality=1；RA1.14对应8抽头Lanczos，不更改全局配置。异步回调运行时RA禁用动态rate control，1:1 nearest除初始延迟可不改变样本，因此nearest不是已确认根因，此改动仅为可回退的播放端对照。

新增有界采样诊断：独立音频回调只在RAM里追加最早10秒活跃BGM的48kHz双声道16位、送前端之前的PCM（最多1.92MB），并用原子计数记录混音耗时、前端提交耗时、BGM活跃期间回调起始间隔及短接收批次。内存前缀发布后永不覆盖，主线程可以安全导出。运行中音频线程不写卡，不增加动态库依赖。正常关闭游戏/退出时保存logs/audio-capture.wav及audio-status.txt。每进程仅一个10秒窗口，优先用于从列表首先启动梦见的复测；强制断电无法保证导出。

下一步实际复测：保持可用的正常音量，从列表首先进入梦见，播放有问题的音乐至少10秒并切换菜单/正文，然后正常退出。若仍发炸，读卡比较捕获PCM与原音乐、回调间隔，再定位核心输出或前端/设备路径。该采样点早于RetroArch重采样及ALSA，不能将干净PCM直接等同于扬声器正常。
