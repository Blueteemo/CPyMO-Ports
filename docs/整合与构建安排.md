## RG35XX 1.0.0 候选

1. 在独立构建副本中从 `platforms/rg35xx` 运行现有 ARM 构建入口。使用已验收环境的 ARM/uClibc SDK、Clang 21.1.8、LLD、LLVM objdump、readelf 和 Python 3。先复建迁移后的原定稿并记录与旧产物的差异，如哈希不同，先核对输入、SDK、路径与编译器。随后在候选提交中同步核心报告版本、游戏列表底栏、核心和启动器日志，复核专用 .info 是否纳入部署。游戏脚本兼容版本、Libretro ABI 与存档格式沿用原值。

   ```sh
   cd platforms/rg35xx
   SDK=/path/to/arm-miyoo-linux-uclibcgnueabi_sdk-buildroot BUILD=/isolated/build-rg35xx bash tools/build_arm_clang_lld.sh softfp
   ```

2. 以 v0.24.5 完整安装包为基底，合入验收更新所对应的启动器、新编译的核心和开场图，保留已验收的图标、字体、许可和应用配置。校对版本、文件白名单、ZIP 成员哈希与写入路径，拟交付 `CPyMO_RG35XX_1.0.0_GarlicOS.zip`。现有定稿核心 SHA-256 为 `a5366d643e57ab9b44e9edb0ff4f5b67bdf3a530c9fc2ba5b402441ffe214e29`，用于证明迁移基线。1.0.0 新核心有自己的构建记录和哈希。
3. 升级按文件覆盖，保留已有 `CPyMO_SAVE_ROOT`，默认查找 `Roms/APPS/saves/`、`Roms/CPyMO_saves/`，并保留各游戏内的 `save/`。升级前记录自定义存档根和自定义启动器设置。用临时卡目录模拟绝对自定义路径，核对旧档可读、新档写回同一游戏子目录。同步保护游戏目录、`output-volume.txt`、自定义 `retroarch-cpymo.cfg` 及全局 RetroArch 配置和 `volume.cfg`。备份被覆盖的应用文件，回退时保留升级后产生的新档。
4. 运行 ARM/QEMU 启动、回到游戏列表、存档读档及旧档回归。实机用候选验证冷启动、首次安装、从 0.24.5 覆盖升级、存读档及回退。正式包在这些检查后冻结。

1.
